多模态 Embedding × 推荐系统：2024–2026 工业落地综述

编译于 2026-11-13 · 面向一线推荐算法工程师的技术选型参考 · 基于 deep-research fan-out + 对抗验证（11 条高置信论断、21/25 claim 通过 3 轮验证）
TL;DR　2024–2026 工业界多模态推荐的主旋律是「从冻结两阶段 → 端到端联合训练 / 适配器对齐 / 生成式语义 ID」三条路径同时演进。 代表工作： ByteDance LEMUR（Douyin Search/Ads 端到端联合训练，CTR 梯度回传到多模态 Transformer）、 Xiaohongshu IDProxy（冻结 MLLM + coarse-to-fine adapter + 残差门控，Content Feed & Display Ads 全量）、 ByteDance SAIL-Embedding（LLM 作为 omni-modal 融合主干 + 推荐协同蒸馏）、 MMGRec / TIGER / OneRec 代表的 RQ-VAE 语义 ID 生成式推荐、 以及 Zalando VCG 证明的「冻结 CLIP + 近期性加权」在中长尾场景的最小可行形态（+50% 完播率全量上线）。

核心工程挑战收敛于三点：防坍缩（positional collapse）、控漂移（上游 MLLM 版本升级）、压延迟（MLLM 离线化为 knowledge provider）。

1. 背景动机：为什么 2024-2026 多模态会卷到排序层

此前 3 年（2021-2023）多模态在推荐系统中的典型角色是召回侧 side info —— 用冻结的 CLIP / BERT / ViT 产出 item embedding 做 i2i 召回、相似度检索、冷启动兜底；排序层仍由海量 ID embedding + 行为序列 + target attention 承载主要权重。进入 2024 年后，这一分工被三股力量打破：

  1. LLM / MLLM 的内容理解上限大幅抬升，让「用文本/视觉表征直接驱动排序」第一次具备工程可行性，不再是 cold-start-only 的兜底方案。
  2. ID embedding 的 scaling 边际开始收敛：字节的 RankMixer、OneTrans 等架构都把 scaling 讨论推到 "token/parameter/data" 三轴，而 ID 侧的边际 token 质量已不如多模态内容侧。
  3. 生成式推荐（TIGER → OneRec） 把 item ID 本身替换为「语义 ID 序列」，从接口上就要求内容理解必须深入到排序甚至生成环节。

2026 年末的工业界共识是：多模态 embedding 不再是"要不要用"的问题，而是"用哪条路径接入 + 如何对齐协同信号 + 如何控成本"的问题。LEMUR 论文开篇即批评传统两阶段 pipeline 的「多模态目标与推荐目标错配」问题，并提出端到端联合优化（arXiv 2511.10962）。

2. 技术路径分类：四种接入方式 × 三种对齐范式

2.1 接入方式（Where）

接入位置做法代表工作优势 / 代价
① 作为 Side Info 特征 多模态 embedding 单独走一列 MLP/投影，与 ID 特征 concat 后进入主模型 早期 CLIP+CTR 系列、PAD baseline 实现简单；但在大模型排序结构中几乎被 ID embedding "淹没"，IDProxy 消融显示这种 w/o Structure Reuse 方案仅 +0.08% AUC
② 替代 / 增强 ID Embedding 多模态 proxy 直接注入到排序模型的 item-ID 槽位、交互模块、target-attention 序列路径 Xiaohongshu IDProxy 复用已有排序结构的 "协同过滤先验"，消融显示 +0.14% AUC（比仅拼接高 75%）
③ 融合到用户序列 把用户历史 item 的多模态 embedding 作为序列 token，经自注意力/target attention HLLM 家族、AlmostRec（LMM 做骨干）、Adapter-RankMixer 直接受益于 LLM-style scaling；但训练/推理开销显著上升
④ Cross-Attention / Adapter 多模态表征作为 Key/Value，排序模型 query；或通过轻量 adapter 模块做投影和融合 CPMM（Neurocomputing 2025）、Adapter-to-RankMixer 模态可插拔、训练参数量小；但 adapter 容量上限决定了迁移效果上限

2.2 对齐范式（How）

通用多模态预训练（CLIP / InternVL / LLaVA / Qwen-VL）的表征空间与推荐协同空间天然存在 gap，CPMM 等工作明确指出这个 gap 来自「预训练数据 ≠ 推荐数据」和「CLIP 不编码协同信号」。2024-2026 的三种主流对齐范式：

对齐范式核心思想代表损失 / 机制代表工作
A. 对比对齐（InfoNCE / proxy） 把 MLLM 表征拉向排序模型 ID embedding 的分布 InfoNCE + 频次阈值过滤不可靠 ID；MLP adaptor + 残差门控 Xiaohongshu IDProxy（arXiv 2603.01590）
B. 分布对齐（MMD / 分布级） 在分布级别而非样本级别匹配多模态与协同表征 Multi-Kernel MMD（5 Gaussian characteristic kernels）+ triple-expert 解耦 PAD（CityU + Tencent, arXiv 2412.04107）
C. 语义 ID 量化（RQ-VAE） 把连续多模态表征量化为离散 "语义 token" 序列，接入自回归生成式推荐 Graph RQ-VAE 层次残差量化 → Rec-ID MMGRec（arXiv 2404.16555）、TIGER、OneRec
D. 锚点对齐（Anchor-based） 避免模态表征直接相互拉近导致的 positional collapse；用融合 projection 作为间接锚点 Anchor-Aligned Learning + Anchor-Modality Preservation AnchorRec（arXiv 2603.12726）
E. 端到端联合训练（gradient-all-the-way） CTR loss 的梯度直接回传到多模态 Transformer 20% 样本走完整反向 + memory-bank 缓存其余 80% LEMUR（ByteDance, CIKM 2026, arXiv 2511.10962）
F. 协同蒸馏（distill-from-production） 把生产侧多个 ID embedding 投影后与多模态表征对齐，兼顾 i2i 辅助任务 Collaboration-aware Recommendation Enhancement（sequence-to-item + ID-to-item） SAIL-Embedding（ByteDance Douyin, arXiv 2510.12709）

3. 代表性工作对比

以下 6 个工作覆盖了 2025–2026 工业界 / 学术界的主要范式分支，均通过了 deep-research 的 3 轮对抗验证（部分为 2/0 置信）。

3.1 LEMUR — 端到端联合训练的旗帜 Douyin Search/Ads 已部署

  • 出处：ByteDance, CIKM 2026 Applied Track（arXiv 2511.10962）
  • 核心机制：CTR loss 的梯度直接回传到多模态 Transformer 的首层；为控成本只对 20% 样本走完整前向/反向，其余使用 memory-bank 缓存。训练样本 3B。
  • 线上效果：Douyin Search 14 天 A/B，T 检验显著，+0.81% QAUC、-0.843% 查询改写率（QCR），自报增益为两阶段 baseline 的 约 5 倍；同期部署于 Douyin Advertisement。
  • 水分警告：论文宣称的 "end-to-end from raw data" 实际是 "采样式端到端"（仅 20% 完整反向），且视频输入前已经过 OCR/ASR/封面帧 caption 文本化，并非直接从像素端到端。

3.2 IDProxy — 冻结 MLLM + 适配器对齐的工程典范 小红书 Content Feed + Display Ads 全量

  • 出处：Xiaohongshu + SJTU + Fudan, RecSys 2026 Industry Oral（ACM / arXiv 2603.01590）
  • 两阶段 coarse-to-fine 框架：
    • Stage 1 · Proxy Alignment Loss (PAL)：InfoNCE 把 MLLM (InternVL) 投影拉向排序模型的 ID embedding，并用频次阈值 τ 过滤低频 ID 目标，防止把不可靠 ID 学成"锚"。
    • Stage 2 · Fine Proxy：从 MLLM 的三层聚类（浅/中/深）抽取 hidden states，经 MLP adaptor 融合，再用 σ(W_g·[coarse, fine]) 残差门控，以 CTR loss 端到端微调（MLLM 保持冻结）。
  • 核心工程洞察（Structure Reuse）：把 coarse/fine proxy 同时注入排序模型的 item-ID 槽位、特征交互模块、target-attention 序列路径。消融 Table 1：
    • v4 w/o Structure Reuse（仅作为 side info 拼接）= +0.08% AUC
    • v5 Full = +0.14% AUC（+75% 相对提升）
    结论："内容信号必须接入排序模型已有的协同过滤结构，而非新增一列特征"。
  • 线上效果：Display Ads +1.28% impression / +1.93% ADVV / +1.73% cost / +0.23% CTR；Content Feed +0.22% time spent。

3.3 SAIL-Embedding — LLM 作 omni-modal 融合主干 ByteDance Douyin SAIL Team

  • 出处：ByteDance + CUHK MMLab, 2025-10（arXiv 2510.12709）
  • 架构：Vision Perceiver 把每帧压缩为 16 latent tokens；CLAP 编码音频；统一映射到 LLM token 空间，LLM 本身作为 omni-modal fusion backbone。
  • 对齐推荐语义 — Collaboration-aware Recommendation Enhancement (CRE)：
    • Sequence-to-item 对比：Single-Peak / Multi-Peak collaboration-aware 变体
    • ID-to-item 蒸馏：把生产侧多个推荐系统的 ID embedding 投影后与 omni-modal 内容表征对齐，并加 i2i 检索辅助任务
  • 生产状态：HuggingFace 已开源 BytedanceDouyinContent collection；线上 A/B 具体数字（+0.5% 7日 LT 等）在验证轮中被判 "sources insufficient"（1-0 弃权），仅作者口径未被独立确认。

3.4 MMGRec — 多模态生成式推荐 生成式 SID 家族

  • 出处：arXiv 2404.16555
  • 核心：Graph RQ-VAE 对多模态+协同信号做层次残差量化，为每个 item 分配离散 Rec-ID（语义 token 序列）；再用 Transformer 以用户历史序列自回归生成被推荐 item 的 Rec-ID。
  • 定位：与 Google TIGER、Kuaishou OneRec 构成同一个 "生成式语义 ID autoregressive" 家族。关键差异是量化器同时融合视觉、文本和 CF 协同信号。

3.5 PAD — LLM 作离线知识提供者 Tencent + CityU

  • 出处：arXiv 2412.04107
  • 三阶段 pipeline：Pre-train → Align → Disentangle。冻结 Llama3-8B 得到 4096 维文本表征经 MLP 投影，与 SASRec 的协同 embedding 对齐。
  • 对齐损失：L = L_REC + γ · L_MK-MMD, γ=0.1，用 5 个 Gaussian characteristic kernels（相比 CTRL 的 cosine/linear 具备 injective 分布区分能力）。
  • 解耦：triple-expert（一个 aligned expert + 两个 modality-specific experts）分离语义与协同信号。
  • 工程价值：彻底回避 LLM 在线推理延迟（LLM 只在离线训练用）。

3.6 AnchorRec — Positional Collapse 的首次命名 学术新概念

  • 出处：arXiv 2603.12726（2026-03，5 页短文）
  • failure mode 定义：当图像和文本 embedding 被直接拉向共享空间时，会 坍缩到几乎相同位置，丢失互补模态特异性。论文用 t-SNE 在 AlignRec embedding 上可视化。
  • 解法：用融合 projection p_mm 作为 shared anchor；Anchor-Aligned Learning (InfoNCE) + Anchor-Modality Preservation 做 间接 anchor-based alignment in lightweight projection domain，让 main embedding h 保留模态结构、projection p 负责对齐。
  • 注意：positional collapse 术语目前仅由此论文引入，尚未成为业界共识名词，引用时应注明出处。

3.7 Zalando VCG — 最小可行形态的工程基线 70M 用户 / 25 市场 全量上线

  • 出处：Zalando SE, RecSys 2025 EARL Workshop（arXiv 2507.19346）
  • 架构：两塔，视频塔 = 均匀采样帧的 CLIP mean-pool（e_v = (1/m) Σ E_CLIP(frame_j)）；用户塔 = 用户近期浏览/搜索商品的 CLIP embedding 做指数衰减加权平均（e_u = Σ w_k·E_CLIP(s_k) / Σ w_k）；dot-product 评分。
  • 冷启动：以"全局热门商品 embedding" 兜底 + Browse/Search few-shot 微调。
  • 线上效果：A/B 测试 +50% 视频完整度 ≥50% 观看（CI 22%-78%，不含 0），已全量上线。
  • 启示：即便不做端到端联合训练、不做 adapter 对齐，"冻结 CLIP + 近期性加权" 在跨 domain（时尚商品 ↔ 短视频）靠共享 CLIP 空间就能匹配——中长尾 e-commerce 短视频场景的工程下限非常低。

3.8 AlmostRec — LMM 直接做序列推荐骨干 Tsinghua, ICMR 2025

  • 出处：清华 Xin Wang 组, ICMR 2025（PDF）
  • 核心：用 LLaVa-1.5-7B 替代文本 LLM 做序列推荐骨干，联合利用历史 item 的 ID、文本描述和图像。
  • 定位：把推荐当作多模态指令任务，与 HLLM / NoteLLM-2 同方向但更激进（LMM 而非纯文本 LLM）。

5. 关键挑战与开放问题

5.1 Positional Collapse（表征坍缩）

首次由 AnchorRec (2026-03) 命名：直接把图像和文本 embedding 拉向共享空间会导致 t-SNE 上几乎同位置坍缩，丢失互补模态特异性。缓解策略：间接锚点对齐（AnchorRec）、分布级而非样本级对齐（PAD 的 MK-MMD）、残差门控保留原模态信号（IDProxy）。

5.2 协同信号注入（Structure Reuse 比新增特征更重要）

IDProxy 的消融给出了近期最清晰的量化证据：把多模态 proxy 注入 ID 槽位/交互模块/target-attention 的 Structure Reuse 方案（+0.14%）比单纯拼接 side info（+0.08%）多 75% 的 AUC 增益。核心机制是复用排序模型已学到的"协同过滤先验"，而非让多模态特征独自跟 ID 特征在最后一层争权重。

5.3 端到端 vs 冻结适配器：范式选择的工程权衡

维度端到端（LEMUR 路径）冻结 + Adapter（IDProxy / PAD 路径）
训练成本高（3B 样本 + 多模态 Transformer 反传，但可采样到 20%）中（MLLM 冻结只做前向缓存）
Serving 延迟高（多模态 Transformer 在线推理）低（PAD 可完全离线；IDProxy 仅 adapter 在线）
自报增益约 5× 两阶段 baselineAds +0.23% CTR / Feed +0.22% time spent
版本一致性差（MLLM 升级需联合重训）好（MLLM 冻结快照 + adapter 增量）
适用场景搜索/广告等高 ARPU 且训练算力充足的场景内容 Feed、冷启动、长尾 item

开放问题：目前没有可复现的 benchmark 能同时评估这两种范式的训练算力/serving 成本/增益幅度的量化对比。

5.4 生成式语义 ID 的码本运维

RQ-VAE / 语义 ID 生成式推荐（MMGRec、TIGER、OneRec）在工业界面临三个未公开的工程问题：

  • 码本利用率：长尾 item 是否塌缩到少量 code？
  • 码本漂移：多模态编码器升级后，Rec-ID 空间是否整体迁移？如何做热更新？
  • 新 item 的 Rec-ID 分配：冷启动 item 如何在线生成一致的 Rec-ID？

目前公开文献几乎不涉及码本运维工程细节。这是 2026-2027 最有价值的开放方向之一。

5.5 版本漂移（Upstream MLLM Drift）

当上游 MLLM 升级（InternVL → InternVL2，LLaVA-1.5 → LLaVA-1.6），下游排序模型往往需要大规模回灌历史 item 的 embedding。工业界的实际应对策略（增量蒸馏？双版本并行？冻结时间窗？）缺乏公开资料。SAIL-Embedding 的 ID-to-item 蒸馏实际已经隐含了一种"把多个版本 ID embedding 当作教师信号"的机制，但未展开讨论。

5.6 存储成本 & 推理延迟

  • 存储：MLLM 隐藏维度 4096，Item 库过亿时 embedding 存储可达 TB 级。IDProxy 用 MLP adaptor 压到低维、PAD 用 triple-expert 再压缩、SAIL-Embedding 用 16 latent tokens/帧，都是在做类似权衡。
  • 延迟：PAD 的"LLM 作为离线 knowledge provider"是最极端的方案（LLM 完全不在线）；LEMUR 的"20% 完整反向 + 80% memory-bank"是训练侧的采样折衷；IDProxy 冻结 MLLM 推理但仍让 adapter 在线。
